# ct-translate — 治験文書 翻訳ハーネス（Claude Code 単独・実験用）

Foundry/Azure を使わず、**Claude Code だけ**で「用語集準拠 ＋ 逆翻訳投票検証 ＋ 出典紐付け」の翻訳を回す最小実験環境。PCI のプロセスを *files + サブエージェント + git* に畳んだもの。

## これは何か（中身の地図）

| 場所 | 役割 |
|---|---|
| `.claude/skills/translate/SKILL.md` | ハーネス（翻訳の手順・Mode 判定・検証） |
| `CLAUDE.md` | ガードレール（義務表現・数値・禁忌は保存 等の絶対ルール） |
| `glossary/*.md` | 用語集（grep で JIT 注入、ファイル順で優先度解決） |
| `sources/` | 原文（合成ダミー同梱） |
| `output/` | 確定訳（出典コメント付き） |
| `memory.md` | 翻訳メモリ（確定対訳を追記＝フライホイール） |
| `experiments/run-log.md` | 4 段ラダーの比較記録 |

> 📖 **なぜ `glossary/*.md` という方式を選んだか**は [GROUNDING.md](GROUNDING.md) を参照 — グラウンディング5方式（用語集/Dynamic Dictionary/Custom Translator/AdaptCT/AI Search RAG）の比較と、①を選んだ理由・③④⑤に進む分岐点を整理。

## 使い方 — 4 段ラダーで「何がどれだけ効くか」を測る

このフォルダで Claude Code を開き、**同じ原文**に対して順に投げる:

1. `sources/protocol-sample.md` を、**用語集なし・検証なし**で JA→EN 翻訳して　…（0 素訳）
2. 同じものを、**用語集ありで**翻訳して　…（1 ＋用語集）
3. **SKILL の手順どおり**（Mode 判定・出典付与込み）で翻訳して　…（2 ＋SKILL）
4. **逆翻訳投票つき（DW）**で翻訳して　…（3 ＋DW）

各回の結果を `experiments/run-log.md` に記録 → **用語集と DW の寄与が数字で出る**（人手修正率・用語逸脱・意味欠落の検出数）。

> 💡 Foundry で訳した同じダミー原文を `sources/` に追加すれば、既存 GPT-4o(+AdaptCT) 結果との直接 A/B になる。

## 用語集の育て方（構築と利用）

- **構築**: `p0-client.md`（顧客指定訳・最優先、手で入れる）＋ 確定訳が `memory.md`→`p2-house.md` に昇格（自動で太る）＋ 未知語は WebFetch で引いて `p3-official.md` に**追記してキャッシュ**
- **利用**: grep して P0→P1→P2→P3 の**先勝ち**。層間不一致は `⚠️要確認` で人間へ
- ⚠️ **毎回 web を引かない**。答えはローカルに固定（訳ブレ＝フライホイール破綻を防ぐ）

## 別アカウント / 会社への移植

このフォルダは **全部ただのファイル**で、どの Claude アカウントにも縛られない。

1. ローカルで開発・検証（個人アカウント）
2. 会社の repo（GitHub / Azure DevOps）に push、または会社マシンにコピー
3. そのマシンで Claude Code を **会社アカウント / 会社 API キー**で認証 → そのまま同じに動く

- **持っていくもの**: このフォルダ一式（用語集の蓄積も含む）
- **持っていかないもの**: API キー等の**秘密**（環境変数・秘密ストアで各環境に設定。`.gitignore` 済み）

## 移植と精度の鉄則（重要）

**アカウントは自由に変えてよい。モデルは固定し、変えるときは変更管理（リバリデーション）。**

| 変更 | 出力精度への影響 |
|---|---|
| Claude **アカウント**（個人→会社）／走らせる**ホスト**／**API 経由**（Anthropic 直 ↔ Foundry ↔ Bedrock、同一モデル） | **変わらない**（鍵・場所が変わるだけ。同一モデルなら実質同等） |
| **モデルそのもの**を変える（Claude→他、Opus→Haiku 等）／**モデルのバージョン**が変わる | **変わる**（モデルは品質の最大の決定要因） |

- 本番では**使用モデルとバージョンを明記（pin）**する。
- モデルを変えるときは**変更管理イベント**として扱い、`experiments/run-log.md` の 4 段ラダーで**再評価（Part 11 リバリデーション）**する。
- ハーネス（用語集・ガードレール・逆翻訳投票）は精度を**モデル非依存の方向に安定させる**が、生の流暢さ・ニュアンスはモデル依存が残る（＝完全非依存にはならない）。
- 期待値は「**同じ訳文が毎回出る**」ではなく「**品質が毎回担保される**」（LLM は同条件でもビット単位では揺れる。用語集＋逆翻訳投票がその揺れを critical な軸で抑える）。

## コスト

- **Claude API のトークンのみ**（Azure 不要）。CSR 級 1 本で数千円オーダー。
- 品質が要るのでモデルは **Claude（クラウド API）**。ローカルモデルは品質が落ちる。
